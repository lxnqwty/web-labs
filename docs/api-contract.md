# Контракт API

Базовый адрес API: `http://localhost:5000`. Формат обмена — JSON. Клиент Vue обращается к ASP.NET Core, а не к PostgreSQL напрямую. Имена полей в JSON соответствуют модели данных.

## Методы и ответы

| Метод и путь | Тело запроса | Успешный ответ | Возможные ошибки |
|---|---|---|---|
| `GET /api/activities` | — | `200 OK`, массив записей; если записей нет, возвращается `[]` | `401 Unauthorized`, `403 Forbidden` |
| `GET /api/activities/{id}` | — | `200 OK`, одна запись | `404 Not Found`, `401 Unauthorized`, `403 Forbidden` |
| `POST /api/activities` | `title`, `categoryId`, `description` | `201 Created`, созданная запись с `id`, `number` и статусом `New` | `400 Bad Request`, `401 Unauthorized`, `403 Forbidden` |
| `PATCH /api/activities/{id}/assignee` | `assigneeUserId` | `200 OK`, запись с обновлённым исполнителем | `400 Bad Request`, `401 Unauthorized`, `403 Forbidden`, `404 Not Found` |
| `PATCH /api/activities/{id}/status` | `status` | `200 OK`, запись с обновлённым статусом | `400 Bad Request`, `401 Unauthorized`, `403 Forbidden`, `404 Not Found`, `409 Conflict` |

Назначение проверяющего и изменение статуса являются разными операциями. Общего пути `/update` нет. Метод `DELETE` не предусмотрен: отмена обозначается статусом `Cancelled`.

## Примеры JSON

### Создание записи

`POST /api/activities`

```json
{
  "title": "Участие в научной конференции",
  "categoryId": 2,
  "description": "Подготовлен и представлен доклад по результатам учебного исследования."
}
```

Ответ `201 Created` (пример):

```json
{
  "id": 104,
  "number": 1004,
  "title": "Участие в научной конференции",
  "description": "Подготовлен и представлен доклад по результатам учебного исследования.",
  "status": "New",
  "categoryId": 2,
  "createdByUserId": 17,
  "assigneeUserId": null
}
```

Клиент при создании не присылает `id`, `number`, `status`, `createdByUserId` или `assigneeUserId`. Сервер создаёт идентификаторы и номер, устанавливает `New`, определяет автора из текущей сессии, а исполнителя оставляет пустым до отдельного назначения. Числа в примере иллюстративны.

### Получение списка

`GET /api/activities`

Ответ `200 OK` (сокращённый пример):

```json
[
  {
    "id": 104,
    "number": 1004,
    "title": "Участие в научной конференции",
    "description": "Подготовлен и представлен доклад по результатам учебного исследования.",
    "status": "New",
    "categoryId": 2,
    "createdByUserId": 17,
    "assigneeUserId": null
  }
]
```

Если записей нет, API возвращает `200 OK` и пустой массив `[]`, а не `404`.

### Получение одной записи

`GET /api/activities/104`

При существующей записи возвращается `200 OK` и объект этой записи. Если записи с таким `id` нет, сервер возвращает `404 Not Found`.

### Назначение проверяющего

`PATCH /api/activities/104/assignee`

```json
{
  "assigneeUserId": 23
}
```

Ответ `200 OK` содержит обновлённую запись. Сервер проверяет, что пользователь `23` существует и может выполнять роль проверяющего. Назначение не должно автоматически менять статус активности.

### Перевод в работу

`PATCH /api/activities/104/status`

```json
{
  "status": "InProgress"
}
```

Ответ `200 OK` содержит запись со статусом `InProgress`. Сервер проверяет полномочия текущего пользователя и допустимость перехода. Например, назначенный проверяющий может перевести свою запись из `New` в `InProgress`; попытка изменить чужую запись отклоняется. Конфликт состояния или недопустимый переход может возвращать `409 Conflict`.

## Формат ошибок

Ошибки возвращаются с подходящим HTTP-кодом и коротким описанием. Например:

```json
{
  "error": "ValidationError",
  "message": "Поле title должно содержать от 5 до 80 символов."
}
```

`400` означает некорректные данные или недопустимое значение; `401` — пользователь не вошёл в систему; `403` — у пользователя нет прав; `404` — запись или связанный объект не найден; `409` — конфликт статуса или недопустимый переход. Точные детали реализации уточняются в последующих лабораторных.

## Словарь статусов

| Код API/БД | Отображаемая подпись |
|---|---|
| `New` | Новая |
| `InProgress` | На проверке |
| `Closed` | Подтверждена |
| `Cancelled` | Отклонена / отменена |
