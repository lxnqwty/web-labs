# Контракт REST API

Базовый адрес: `http://localhost:5000`. Формат обмена — JSON. Vue-клиент обращается к ASP.NET Core API; данные ЛР8 хранятся в памяти backend и очищаются после его перезапуска.

## Ресурс заявки

| Метод и путь | Тело запроса | Успешный ответ | Ошибки |
|---|---|---|---|
| `GET /api/tickets` | — | `200 OK`, массив; пустой список — `[]` | `500` |
| `GET /api/tickets/{id}` | — | `200 OK`, одна заявка | `404`, `500` |
| `POST /api/tickets` | `title`, `categoryId`, `description` | `201 Created`, заявка с `id`, `number`, `status: New` | `400`, `500` |
| `PATCH /api/tickets/{id}/assignee` | `assigneeUserId` | `200 OK`, обновлённая заявка | `400`, `404`, `500` |
| `PATCH /api/tickets/{id}/status` | `status` | `200 OK`, обновлённая заявка | `400`, `404`, `409`, `500` |

Удаление не предусмотрено. Назначение исполнителя и смена статуса — отдельные операции.

## Создание

`POST /api/tickets`

```json
{
  "title": "Разработка командного веб-проекта",
  "categoryId": 3,
  "description": "Создание прототипа цифрового сервиса в рамках проектной деятельности."
}
```

Сервер сам создаёт `id` и `number`, устанавливает `status: "New"` и `assigneeUserId: null`. Клиент не может назначить эти поля при создании.

Проверки: `title` — 5–80 символов; `description` — 10–500 символов; `categoryId` — целое число больше нуля. Нарушение возвращает `400 Bad Request`.

## Чтение

- `GET /api/tickets` возвращает `200 OK` и массив. Если заявок нет, тело ответа — `[]`.
- `GET /api/tickets/{id}` возвращает `200 OK` для существующей заявки и `404 Not Found` для неизвестного идентификатора.

## Назначение исполнителя

`PATCH /api/tickets/1/assignee`

```json
{ "assigneeUserId": 5 }
```

Идентификатор исполнителя должен быть положительным целым числом. Назначение не меняет статус автоматически.

## Изменение статуса

`PATCH /api/tickets/1/status`

```json
{ "status": "InProgress" }
```

Допустимые статусы: `New`, `InProgress`, `Closed`, `Cancelled`. Для перехода в `InProgress` исполнитель должен быть назначен, а заголовок `X-User-Id` должен совпадать с `assigneeUserId`. Закрыть можно только заявку в статусе `InProgress`, также только назначенному исполнителю. Недопустимые переходы возвращают `409 Conflict`.

## Формат ошибок и логирование

Ошибки API возвращаются в формате `ProblemDetails`. Неожиданные исключения записываются серверным ILogger с названием операции, идентификатором заявки (если он есть) и типом исключения. Клиент получает безопасное сообщение без stack trace и локальных путей.

## Словарь статусов

| Код | Подпись |
|---|---|
| `New` | Новая |
| `InProgress` | На проверке |
| `Closed` | Подтверждена |
| `Cancelled` | Отклонена |
