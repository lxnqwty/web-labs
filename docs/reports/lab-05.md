# Отчёт по лабораторной работе №5

**Тема:** Vue 3 — форма и список в памяти.

## Цель работы

Связать форму создания активности с общим реактивным массивом, реализовать клиентскую проверку введённых данных и отображение новой записи в списке без обращения к серверу.

## Выполненная работа

1. В TicketNew.vue создано реактивное состояние формы с полями темы, категории и описания.
2. Поля связаны с состоянием через v-model; для categoryId используется модификатор .number, поэтому идентификатор хранится числом.
3. Отправка выполняется через @submit.prevent, поэтому стандартная перезагрузка страницы браузером не происходит.
4. Добавлена проверка темы (5–80 символов после trim), категории (целое положительное значение из справочника) и описания (10–500 символов). Ошибки выводятся рядом с соответствующими полями.
5. В ticketsStore.js добавлена общая функция addItem. Она создаёт уникальный в рамках текущей сессии id, временный номер TMP-id и устанавливает статус New.
6. После успешного добавления форма очищается, а приложение переходит на маршрут /, где новая запись отображается в таблице.

В проекте используется поле categoryId вместо условного siteId из методички, поскольку оно соответствует справочнику категорий предметной области проекта.

## Контрольные сценарии

| Сценарий | Действие | Ожидаемый результат |
|---|---|---|
| Успешное создание | Ввести тему длиной от 5 до 80 символов, выбрать категорию и описание длиной от 10 до 500 символов; отправить форму | Новая строка появляется в списке со статусом «Новая» и временным номером TMP-4 |
| Отказ по теме | Ввести тему abc и отправить форму | Запись не добавляется; под полем темы отображается сообщение об ошибке |
| Проверка типа | Выбрать категорию №2 | В состоянии формы categoryId имеет тип number, значение равно 2 |
| Проверка памяти | Создать запись и обновить страницу клавишей F5 | Новая запись исчезает; это ожидаемо, поскольку серверное хранение ещё не реализовано |

## Запуск и проверка

Из папки frontend выполнить npm install и npm run dev. Открыть http://localhost:5173/new, проверить успешную отправку и отказ для короткой темы, затем обновить список клавишей F5. Production-сборка проверяется командой npm run build.

## Вывод

В ходе выполнения лабораторной работы форма создания активности была связана с единым реактивным хранилищем Vue. Реализованы проверка вводимых значений, добавление записи со статусом New, очистка формы и переход к списку. Данные сохраняются только в оперативной памяти приложения, поэтому после обновления страницы новые записи исчезают. Такое поведение соответствует требованиям лабораторной работы; серверное хранение будет реализовано на следующих этапах.
