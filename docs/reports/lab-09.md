# Отчёт по лабораторной работе №9

**Тема:** PostgreSQL и SQL.

## Цель работы

Создать реляционную схему PostgreSQL для цифрового профиля студента, задать связи и ограничения целостности, добавить учебные данные и подготовить SQL-запросы с фильтрацией, сортировкой, JOIN и GROUP BY.

## Сверка с моделью проекта

В проекте главный объект называется `Activity`, справочник — `Category`, пользователь — `User`. В SQL использованы таблицы `activities`, `categories` и `users`; имена столбцов приведены к `snake_case`.

- `activities.category_id` ссылается на `categories.id`;
- `activities.created_by_user_id` ссылается на `users.id`;
- `activities.assignee_user_id` ссылается на `users.id` и допускает `NULL`;
- `activities.number` — уникальный человекочитаемый номер, отдельный от PK `id`.

## Выполненная работа

1. Создан `db/schema.sql`: таблицы пользователей, категорий и активностей.
2. Добавлены первичные ключи, внешние ключи, уникальные ограничения и CHECK для ролей, длины текста и четырёх статусов `New`, `InProgress`, `Closed`, `Cancelled`.
3. Добавлены индексы по `status` и `category_id` с комментариями о назначении.
4. Создан `db/seed.sql`: три пользователя, три категории и четыре активности — по одной на каждый статус.
5. Создан `db/queries.sql`: запросы для фильтрации, сортировки, JOIN с категориями и пользователями, подсчёта записей через GROUP BY.
6. Обновлён README с командами создания учебной базы и запуска SQL-скриптов.

## Запуск

Требуется установленный PostgreSQL и доступная команда `psql`. Из корня репозитория:

```bash
createdb course_profile
psql -d course_profile -f db/schema.sql
psql -d course_profile -f db/seed.sql
psql -d course_profile -f db/queries.sql
```

Вместо `psql` можно выполнить файлы по очереди через Query Tool в pgAdmin. Пароль PostgreSQL хранится только в локальной конфигурации пользователя и не добавляется в Git.

## Проверка результата

После выполнения скриптов:
- в `users` должны быть три учебных пользователя;
- в `categories` — три категории;
- в `activities` — четыре записи;
- запрос GROUP BY должен вернуть четыре строки со статусами;
- JOIN должен показать название категории и имена пользователей;
- попытка вставить активность с неизвестным статусом, например `Done`, должна завершиться нарушением CHECK.

**Ограничение проверки:** SQL-скрипты подготовлены и проверены на согласованность структуры по исходному коду и модели проекта. Подключение к экземпляру PostgreSQL и фактическое выполнение запросов в среде редактирования не запускались; перед сдачей необходимо выполнить команды выше и приложить реальные результаты или скриншоты pgAdmin.

## Важное разделение с ЛР10

В этой работе создаётся схема и выполняются SQL-запросы вручную. ASP.NET Core API из ЛР8 пока продолжает хранить заявки в памяти и не подключён к PostgreSQL. Подключение C# к базе через EF Core относится к следующей лабораторной работе.
