# Отчёт по лабораторной работе №7

**Тема:** ASP.NET Core — каркас Web API.

## Цель работы

Создать в репозитории отдельный backend на ASP.NET Core, настроить запуск по HTTP на порту 5000, подключить Swagger, добавить служебные маршруты `/health` и `/info`, а также подготовить структуру слоёв и регистрацию сервиса через Dependency Injection.

## Выполненная работа

1. В корне репозитория создан каталог `backend/`, расположенный рядом с `frontend/` и `docs/`.
2. Создан проект ASP.NET Core Web API на .NET 8 с файлом проекта `backend.csproj`.
3. Подключён пакет `Swashbuckle.AspNetCore`; в `Program.cs` зарегистрированы генератор Swagger и API Explorer. Swagger UI включается в среде Development.
4. В `Properties/launchSettings.json` задан профиль Development с адресом `http://localhost:5000`.
5. Реализован маршрут `GET /health`, возвращающий текст `ok` с HTTP-статусом 200. Маршрут не принимает поля заявки и проверяет только доступность процесса.
6. Реализован маршрут `GET /info`, возвращающий имя приложения, текущую среду выполнения и учебную версию.
7. Подготовлены каталоги `Controllers`, `Services`, `Models` и `Data`. В папке Controllers размещено описание назначения слоя; в Data — описание будущего слоя доступа к данным.
8. В Services добавлены интерфейс `IAppInfoService` и реализация `AppInfoService`. Сервис получает сведения о среде через `IHostEnvironment`.
9. Сервис зарегистрирован в DI-контейнере через `AddSingleton<IAppInfoService, AppInfoService>()` и внедряется в обработчик маршрута `/info`. Создание сервиса вручную через `new` в обработчике не используется.
10. В корневой `.gitignore` добавлены исключения для каталогов сборки .NET `bin/` и `obj/`, а также локальных файлов Visual Studio.
11. README дополнен командами запуска backend, адресами Swagger и служебных маршрутов, а также пояснением, что `/health` не означает готовность создания заявок.
12. Добавлена настоящая ссылка на отчёт ЛР7 в разделе документации README.

## Адреса API

| Метод и адрес | Назначение | Ожидаемый результат |
|---|---|---|
| `GET http://localhost:5000/health` | Проверка живости процесса | `200 OK`, текст `ok` |
| `GET http://localhost:5000/info` | Информация о приложении | JSON с именем, средой и версией |
| `http://localhost:5000/swagger` | Интерактивная документация API | Swagger UI в Development |

Пример ответа `/info` в среде разработки:

```json
{
  "application": "Student Profile API",
  "environment": "Development",
  "version": "ЛР7"
}
```

## Команды запуска

Из корня репозитория:

```bash
cd backend
dotnet restore
dotnet run
```

Для проверки после запуска необходимо отдельно открыть Swagger, вызвать `GET /health` и `GET /info`.

## Проверка и ограничения

В этой лабораторной работе реализован только каркас API. Маршруты создания и чтения заявок, валидация данных, хранение в памяти backend и подключение PostgreSQL не реализованы — это последующие этапы курса. Vue-клиент к backend в ЛР7 не подключается.

Команды сборки и запуск приложения в среде выполнения GitHub не выполнялись. Поэтому успешная компиляция и фактические HTTP-ответы должны быть проверены локально командой `dotnet run` и запросами к адресам из таблицы выше.

## Вывод

В ходе выполнения лабораторной работы создан отдельный проект ASP.NET Core Web API на .NET 8. Настроены Swagger и HTTP-порт 5000, добавлены служебные маршруты `/health` и `/info`, подготовлены основные каталоги backend и реализована регистрация сервиса через DI. Серверный каркас подготовлен для дальнейшей реализации API заявок в ЛР8; проверка `/health` при этом рассматривается только как проверка доступности процесса.
